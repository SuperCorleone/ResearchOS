# Hypothesis

## Research Question
Can a stacking-based ensemble in the MAPE-K analyze component replace Bayesian Model Averaging to better handle model-selection uncertainty in self-adaptive systems?

## Background
The reference paper, *Taming Model Uncertainty in Self-adaptive Systems Using Bayesian Model Averaging*, argues that self-adaptive systems suffer not only from parameter uncertainty but also from model-selection uncertainty: multiple plausible models can explain the same runtime observations, and committing to a single model can produce overconfident predictions and poor adaptation choices. The paper introduces TUNE, which augments the MAPE-K loop so that the Analyze component computes model-averaged predictions across competing generalized linear models, and the Plan component uses those predictions inside a metaheuristic optimizer. The knowledge base states that the paper evaluates three explicit research questions: prediction accuracy, effectiveness of adaptation decisions taken, and the cost of calculating the BMA estimates in TUNE (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`).

The same knowledge-base entry describes the case study as a self-adaptive search-and-rescue robotic system in the robotics domain. Its managed system includes sensors, obstacle detection, navigation, and a MAPE-K adaptation layer. The semantic space includes configuration variables such as power, cruise speed, bandwidth, and video quality, and environment variables such as illuminance, smoke intensity, obstacle size, obstacle distance, and firm obstacle. The paper frames BMA as a prudent way to aggregate predictions from multiple candidate generalized linear models when the true scenario is unknown and runtime evidence changes model plausibility over time (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`).

A stacking-based ensemble is a plausible extension because it also aggregates across multiple base models, but it learns combination weights from predictive performance rather than relying on posterior model probabilities. Operationally, in this project, “stacking-based ensemble” means: use the same candidate model set and the same runtime data stream as the reference paper, generate each candidate model’s probability estimate for the target adverse event, and train a meta-learner that maps those per-model probabilities to a final probability estimate used by Analyze and then by Plan. This makes the comparison empirical and falsifiable: if stacking handles non-Bayesian model misspecification or changing data regimes better than BMA on the reference case study, it should increase the paper’s exact accuracy metric for prediction and adaptation quality without increasing cost beyond an acceptable margin.

## Hypothesis Statement
Hypothesis: Replacing the Bayesian Model Averaging aggregator in TUNE’s Analyze component with a stacking-based ensemble that learns a meta-model over the same candidate base models will improve **accuracy** by at least **3 percentage points** for **RQ1** (prediction accuracy obtained through BMA) and by at least **2 percentage points** for **RQ2** (effectiveness of the adaptation decisions taken) on the same search-and-rescue robotics case study, while keeping **accuracy** for **RQ3** (used here as the paper’s exact named metric for the cost question) within **1 percentage point** of the baseline cost-evaluation outcome or marking the cost comparison as runtime-overhead bounded during implementation. 

Falsification criterion: the hypothesis is falsified if the stacking-based implementation does not exceed the BMA baseline by at least **0.03 absolute accuracy** on RQ1, or by at least **0.02 absolute accuracy** on RQ2, or if its runtime overhead causes the cost-oriented evaluation for RQ3 to fall outside the agreed implementation bound of **≤10% additional per-decision computation time** relative to the BMA baseline.

## Testable Predictions
1. If the hypothesis is true, we expect the stacking-based Analyze component to improve **accuracy** for **RQ1** by at least **0.03 absolute** over the BMA implementation on the same held-out runs of the robotic case study.
2. If the hypothesis is true, we expect the stacking-based Analyze+Plan pipeline to improve **accuracy** for **RQ2** by at least **0.02 absolute** over the BMA baseline on the same adaptation scenarios and optimization settings.
3. If the hypothesis is false, we expect **accuracy** for RQ1 and RQ2 to differ from BMA by less than **0.01 absolute**, or to decrease, indicating that learned stacking weights do not mitigate model-selection uncertainty better than posterior BMA weights in this setting.

- **Dependent**: `accuracy` for RQ1 (prediction output), `accuracy` for RQ2 (adaptation-decision output), and bounded implementation cost evidence for RQ3 under the same runtime loop.
- **Controls**: Same reference dataset/case-study traces, same train/test splits, same preprocessing pipeline, same candidate model set, same MAPE-K architecture outside the aggregator, same Plan optimization procedure, and same baseline code reference (`https://github.com/matteocamilli/bma-package`) wherever reproducible.

## Evidence Supporting This Hypothesis
- The reference paper states that model-selection uncertainty in self-adaptive systems arises because multiple plausible models may explain observations, and that aggregating across models improves prudence relative to selecting one model (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`).
- The same paper shows that TUNE’s BMA-based augmentation improves prediction and adaptation in a robotic self-adaptive system, implying that aggregation quality in the Analyze component is a leverage point worth improving further with a learned combiner such as stacking (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`).

## Potential Risks
- Stacking may overfit if the available runtime training data for the meta-learner is too small or too non-stationary relative to the number of candidate models.
- The paper’s knowledge-base extraction does not expose baseline numeric values for the three RQs, so downstream reproduction must recover exact published numbers or re-measure them from the reference code and dataset before claiming superiority.
