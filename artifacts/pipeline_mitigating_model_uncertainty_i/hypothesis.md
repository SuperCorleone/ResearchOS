# Hypothesis

## Research Question
How can stacking-based ensemble methods replace Bayesian Model Averaging (BMA) in the MAPE-K loop to better handle model-selection uncertainty in self-adaptive systems?

## Background
The reference paper, *Taming Model Uncertainty in Self-adaptive Systems Using Bayesian Model Averaging*, introduces TUNE, which augments the MAPE-K loop with Bayesian Model Averaging to mitigate model-selection uncertainty at runtime. In TUNE, the Knowledge component stores a model space of generalized linear models; in the reported robotics case study, each runtime model is a logistic regression over a subset of the semantic-space variables. The Analyze component computes BMA estimates over candidate models, and the Plan component uses those estimates inside a metaheuristic optimizing search to choose a target configuration. The paper's case study is a self-adaptive search-and-rescue robot with configuration variables such as power, cruise speed, bandwidth, and quality, plus environment variables such as illuminance, smoke intensity, obstacle size, obstacle distance, and firm obstacle. The outcome modeled at runtime is the likelihood of a negative event, i.e., failure to satisfy system-level requirements. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`)

The paper explicitly evaluates three research questions: prediction accuracy, effectiveness of adaptation decisions, and computational cost of BMA estimates. The extracted evaluation protocol states these as RQ1, RQ2, and RQ3 respectively, and the knowledge-base extraction labels the paper's exact published metric name as `accuracy` for all three RQs. Although that extraction is coarse and likely compresses distinct operational measurements under one name, downstream comparison must preserve the paper's exact metric naming in this artifact. The paper also states that TUNE uses exhaustive or MCMC exploration of the model space, maintains multiple runtime models in the Knowledge component, and improves adaptation decisions by feeding model-averaged predictions into metaheuristic search. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`)

Stacking is a plausible replacement for BMA because it also combines multiple candidate models, but learns combination weights to optimize out-of-sample predictive performance instead of using posterior model probabilities. Operationally, in this pipeline, "stacking-based ensemble" means: train the same candidate logistic-regression model family used by TUNE on the same robotics dataset, generate out-of-fold predictions under the same train/test split and preprocessing pipeline as the reference paper, fit a meta-learner or constrained weight optimizer over those base-model predictions, and supply the resulting ensemble probability estimates to the same Analyze-to-Plan interface used by TUNE. If stacking yields more accurate probability estimates under model misspecification or correlated candidate models, it may produce better adaptation decisions without violating the original MAPE-K structure. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`; source: `stacking ensemble generalized linear models model averaging adaptation decisions runtime uncertainty` KB retrieval)

## Hypothesis Statement
Replacing the BMA estimator in TUNE's Analyze component with a stacking-based ensemble over the same candidate logistic-regression model space, while keeping the same dataset, train/test split, preprocessing pipeline, adaptation space, and Plan component interface, will improve **accuracy** for prediction and adaptation outcomes by at least **2 percentage points** relative to BMA on the reference robotics case study, while keeping **accuracy** for computational cost no worse than **5 percentage points below** the BMA baseline. 

Operationalization:
- **Replacing BMA** = remove posterior-probability weighting over candidate models and instead combine the same candidate models using stacking weights learned from out-of-fold predictions.
- **Same model space** = the set of candidate GLM/logistic models formed from subsets of the semantic-space variables used in TUNE.
- **Better handle model-selection uncertainty** = achieve higher observed `accuracy` on RQ1 and RQ2 than the BMA baseline under the same evaluation setup.
- **Computational cost acceptable** = the RQ3 `accuracy` proxy used by the baseline extraction is not degraded by more than 5 percentage points; if the later experiment designer recovers a more precise cost operationalization from the paper, that exact paper metric must replace the proxy name while preserving paper alignment.

This hypothesis is falsifiable: it is false if the stacking variant does not exceed the BMA baseline by at least 0.02 on RQ1 and RQ2 `accuracy`, or if its RQ3 `accuracy` is lower than BMA by more than 0.05.

## Testable Predictions
1. If the hypothesis is true, we expect the stacking-based replacement to increase **RQ1 `accuracy` by at least 0.02** over the BMA baseline on the same held-out test split.
2. If the hypothesis is true, we expect the stacking-based replacement to increase **RQ2 `accuracy` by at least 0.02** over the BMA baseline when the same Plan component consumes the ensemble predictions; in an ablation where stacking is removed and BMA is restored, **RQ2 `accuracy` should fall back to within 0.01 of the original BMA result**.
3. If the hypothesis is false, we expect either **RQ1 `accuracy` improvement < 0.02**, or **RQ2 `accuracy` improvement < 0.02**, or **RQ3 `accuracy` to be worse than BMA by more than 0.05** once the exact paper-aligned cost evaluation is implemented.

## Key Variables
- **Independent**: Ensemble method in the Analyze component: BMA weighting vs. stacking-based weighting over the same candidate logistic-regression model space.
- **Dependent**: RQ1 `accuracy`, RQ2 `accuracy`, and RQ3 `accuracy` as extracted from the baseline paper's evaluation protocol.
- **Controls**: Same robotics case-study dataset; same train/test splits; same preprocessing pipeline; same semantic-space variables; same candidate model family; same MAPE-K architecture except for the Analyze aggregation method; same Plan-stage metaheuristic search; same adaptation-space constraints.

## Evidence Supporting This Hypothesis
- TUNE already demonstrates that aggregating across candidate models inside MAPE-K is useful because model uncertainty in the choice of a single runtime model can degrade predictions and planning; this supports testing an alternative aggregation rule rather than reverting to single-model selection. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`)
- The reference architecture cleanly separates runtime models in Knowledge, inference in Analyze, and decision optimization in Plan, which makes the BMA combiner an operationally replaceable component; therefore a stacking-based combiner can be inserted while keeping the rest of the control loop fixed for fair comparison. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`)

## Potential Risks
- The knowledge base currently exposes only coarse metric labels (`accuracy`) and not the paper's exact numeric baseline values or detailed cost formulae, so downstream agents must recover these before claiming definitive reproduction.
- Stacking may overfit if out-of-fold prediction generation is not carefully nested inside the same training protocol as the reference paper, which would make any apparent gain invalid.
- If the reference paper's candidate model space is small and well matched to BMA assumptions, stacking may add variance without enough benefit.
- RQ3 may remain out of scope unless the original implementation boundary and timing instrumentation used by TUNE are reconstructed from code or supplementary material.
