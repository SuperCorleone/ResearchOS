# Hypothesis

## Research Question
Can replacing Bayesian Model Averaging (BMA) with a stacking-based ensemble meta-learner in the MAPE-K Analyze component reduce model-selection uncertainty and improve adaptation quality in self-adaptive systems?

## Background
The reference paper, *Taming Model Uncertainty in Self-adaptive Systems Using Bayesian Model Averaging*, argues that the Analyze component of a MAPE-K loop should not commit to a single explanatory model when multiple plausible models exist. In the paper’s TUNE approach, the Analyze component maintains a model space of candidate Generalized Linear Models (GLMs), updates their posterior plausibility from runtime observations, and computes a model-averaged prediction using Bayesian Model Averaging. That prediction is then passed to the Plan component, which uses metaheuristic optimization to select a target configuration for the managed system. The paper reports that poor predictive modeling in Analyze can lead to missed adaptations or unnecessary adaptations, which then affect system-level qualities such as safety and energy use. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`)

In the reference case study, the managed system is a self-adaptive search-and-rescue robot. The semantic space includes configuration variables such as power, cruise speed, bandwidth, and video quality, plus environment variables such as illuminance, smoke intensity, obstacle size, obstacle distance, and firm obstacle. The original method uses GLMs because the target quantities are probabilistic or distributional predictions over outcomes relevant to requirements. Model-selection uncertainty is operationalized in this pipeline as uncertainty induced by having multiple candidate predictive models for the same target quantity in the Analyze component, where each candidate produces different predictions for the same runtime state. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`)

A stacking-based ensemble is a different operational mechanism for combining candidate models. In this pipeline, “stacking-based ensemble meta-learner” means a supervised combiner trained on out-of-fold predictions from the same candidate base models used in the reference paper, producing a final probability estimate for the target event or target quality variable. Unlike BMA, which weights models by posterior model probability, stacking weights or combines models to optimize predictive performance on held-out data. Therefore, the central empirical question is whether replacing BMA with stacking in Analyze yields better-calibrated predictions and, when those predictions drive the same planning procedure and same data pipeline as the reference paper, better adaptation outcomes.

## Hypothesis Statement
If the Analyze component uses a stacking-based ensemble meta-learner trained on out-of-fold predictions from the same candidate GLM model space as the reference BMA approach, while keeping the same runtime data, train/test splits, preprocessing pipeline, and Plan/Execute logic unchanged, then on the reference robotics case study it will reduce predictive uncertainty error and improve adaptation quality relative to BMA. Operationally, this means the stacking variant will achieve at least 0.02 lower Brier score for the target event prediction and at least 5% fewer requirement-violating adaptation outcomes than the BMA baseline on the same held-out evaluation traces.

## Testable Predictions
1. If the hypothesis is true, we expect: the stacking-based Analyze component to achieve a mean Brier score at least 0.02 lower than the BMA Analyze component on the same held-out test split for the target event probability predicted by the reference pipeline.
2. If the hypothesis is true, we expect: the end-to-end adaptation loop using stacking predictions to reduce the rate of requirement-violating decisions by at least 5.0% relative to the BMA-based loop, measured as `(violating adaptations / total adaptations)` on the same evaluation traces and same planning algorithm.
3. If the hypothesis is false, we expect: either the stacking-based Analyze component improves Brier score by less than 0.01, or the requirement-violating decision rate differs from BMA by less than 2.0%, or stacking increases online analysis cost by more than 10.0% in mean per-decision Analyze latency, eliminating any practical gain.

## Key Variables
- **Independent**: Analyze-component model-combination method, with two levels: (a) Bayesian Model Averaging over the candidate GLM model space from the reference paper, and (b) stacking meta-learner trained on out-of-fold predictions from the same candidate GLMs.
- **Dependent**: (1) predictive accuracy measured by Brier score on held-out traces; (2) calibration quality measured by expected calibration error (ECE) on held-out traces; (3) adaptation quality measured by requirement-violating decision rate on replayed evaluation traces; (4) mean Analyze latency per adaptation decision in milliseconds.
- **Controls**: same dataset as the reference paper; same train/test splits; same preprocessing pipeline; same semantic-space variables; same candidate base-model set; same planning/metaheuristic search procedure; same objective and constraints used by the planner; same managed-system case study; same evaluation metrics and same random seeds where applicable.

## Evidence Supporting This Hypothesis
- The reference paper shows that integrating model combination into Analyze improves prediction quality and downstream adaptation decisions because model-selection uncertainty in self-adaptive systems propagates into planning quality; this supports testing whether a different combination rule can further improve the same pipeline. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`)
- The reference paper explicitly separates candidate-model prediction in Analyze from adaptation search in Plan, which makes the model-combination mechanism an isolated, replaceable component; this supports a controlled ablation where BMA is swapped for stacking while holding the rest of the MAPE-K loop fixed. (source: `concepts/taming_model_uncertainty_in_self_adaptive_systems_using_baye.md`)

## Potential Risks
- The reference paper’s gains may depend on Bayesian posterior updating over models; a stacking combiner may improve held-out prediction but degrade runtime robustness if the environment distribution shifts over time.
- If the original dataset is small or highly imbalanced, the stacking meta-learner may overfit out-of-fold predictions and fail to outperform BMA under the exact train/test splits mandated by the reference setup.

## Reference Paper Details (if improving upon existing work)
- **Paper**: Taming Model Uncertainty in Self-adaptive Systems Using Bayesian Model Averaging
- **Their Method**: The paper proposes TUNE, which augments the MAPE-K loop. In Analyze, it keeps a model space of candidate runtime models `M1..Mn`, each corresponding to a plausible scenario encoded as a Generalized Linear Model (GLM). The paper explicitly discusses GLMs, including logistic regression for Bernoulli/binomial outcomes, and uses Bayesian Model Averaging to compute `p(σ | data) = Σ_i p(σ | Mi, data) * p(Mi | data)`. The knowledge-base excerpt states that Analyze performs “BMA with MCMC exploration” over the model space, updates estimates from observations, and passes an average-model prediction to Plan. Plan then performs metaheuristic optimizing search over the adaptation/configuration space to choose a target configuration.
- **Their Data**: The paper uses an exemplar robotics case study: a self-adaptive search-and-rescue robot. The semantic space includes configuration variables `power` (integer, [0,100]%), `cruise speed` (continuous, [0,5] m/s), `bandwidth` (continuous, [10,50] Mbit/s), and `quality` (categorical: {low, mid, high}); and environment variables `illuminance` (continuous, [40,120000] lux), `smoke intensity` (categorical: {none, thin, thick}), `obstacle size` (continuous, [0,120] ft^3), `obstacle distance` (continuous, [0,10] m), and `firm obstacle` (Boolean: Yes/No). The knowledge-base excerpt does not expose a downloadable dataset filename, but it makes clear that downstream work must reuse the same robotics data/traces, same variable definitions, same train/test splits, and same preprocessing pipeline as the reference paper.
- **Their Evaluation**: The paper states that the empirical evaluation assesses “accuracy, effectiveness, and cost” of the approach. From the excerpt, effectiveness is tied to adaptation outcomes in the robotics domain, where poor predictions cause failures to recognize needed adaptations or unnecessary adaptations that harm dependability attributes such as safety and energy consumption. The system-level requirements listed include maintaining protective distance from obstacles, avoiding human/object misclassification, and reaching target location with enough power. The evaluation therefore must preserve the original experimental setup: same robotics case study, same requirements, same Analyze-to-Plan interface, and same cost/effectiveness measurements used by the paper.
- **What We Change**: We replace only the Analyze-component model combiner. Instead of computing the final prediction by Bayesian Model Averaging over candidate GLMs with posterior model probabilities, we train a stacking-based meta-learner on out-of-fold predictions from those same candidate GLMs and use the meta-learner’s output as the final prediction consumed by Plan. The purpose is to test whether direct held-out optimization of predictive combination reduces predictive error and downstream requirement violations more than posterior averaging.
- **What Must Stay Same**: The robotics dataset/traces from the reference paper; the exact train/test split; the exact preprocessing and feature encoding for the semantic-space variables; the same candidate base-model space; the same managed-system simulator or replay traces; the same planning/metaheuristic search implementation; the same requirement definitions; and the same evaluation metrics for accuracy, effectiveness, and cost. These controls are required for a fair comparison between BMA and stacking.
